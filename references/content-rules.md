# 文本生成规则

仅当任务包含“撰写、改写、扩写、压缩、总结或实质性修改正文”时读取本文件。纯排版、格式修复、校验任务不要读取。

## 1. 信息来源优先级

1. 用户当前明确要求。
2. 用户提供的文件、表格、图片、数据和既有文档。
3. 用户明确要求检索或补充时获得的外部资料。
4. 模型的一般知识只能用于语言组织和必要解释，不能替代缺失的事实依据。

如果来源材料不能支持某个事实、数字、日期、单位、项目名称、人员、结论或因果关系，不要自行补齐。

## 2. 修改已有文档

- 只修改任务要求的内容范围；未要求调整的事实、数据、结构和表述尽量保持。
- 不因为“润色”擅自改变原意、扩大结论、增加政策判断或替换专业术语。
- 不把已有文档整体重写成通用 AI 文风。
- 原文存在明确术语、机构简称、项目名称、指标口径、年份和单位时沿用原口径。

## 3. 新写或扩写正文

- 先依据来源材料组织事实，再进行表达；禁止先写结论再补想象依据。
- 语言应与文档用途一致，正式、准确、克制；避免“综上所述可见”“赋能高质量发展”等无信息量套话，除非上下文确实需要。
- 不写“作为 AI”“根据生成结果”“generated by”等生成过程说明。
- 不伪造引用、文件编号、政策名称、客户、合同、项目金额、市场份额或验收结果。
- 对来源中明确为空、缺失、待定的项目，不自行推断数值。

## 4. 标题与结构

- 标题层级表达内容逻辑，不为了版式凑层级。
- 使用模板既有标题体系；可见编号沿用用户/模板约定，不擅自改造成另一套自动多级编号。
- 对已有文档，除非任务要求重构，不随意改变章节顺序和标题层级。

## 5. 表格与数据

- 表格中的数字、百分比、年份、单位、企业/项目名称必须与来源一致。
- 不为了填满表格补造缺失值；来源为空时保持为空或按用户指定方式标示。
- 文本中引用表格数据时保持同一口径，不做未经要求的换算、四舍五入或合并。
- 格式层面的字号、缩进、宽度和居中由 `normalize_docx.py` 负责，不在写作阶段靠模型逐项记忆。

## 6. 外部补充

只有用户明确要求“检索、核实、补充、扩展”时才使用外部资料。外部资料与用户提供材料发生差异时，应明确区分来源，不静默覆盖原材料。
