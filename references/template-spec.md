# 公文排版Word模板.dotx 参考说明

本文件只记录模板事实和已验证的兼容性经验，供排版诊断、模板维护和 Skill 开发时查阅。日常生成 Word 不应默认读取本文件。

运行时强制规则统一维护在 `config/rules.json`；模板文件 `assets/公文排版Word模板.dotx` 仍是模板定义的最终事实来源。

## 页面与版心

- A4 纵向：`11906 × 16838` twips。
- 上边距：`2098` twips，约 3.70 cm。
- 下边距：`1984` twips，约 3.50 cm。
- 左边距：`1587` twips，约 2.80 cm。
- 右边距：`1474` twips，约 2.60 cm。
- 页眉：`850` twips，约 1.50 cm。
- 页脚：`1417` twips，约 2.50 cm。
- 装订线：0。
- 正文可用宽度约 15.6 cm。
- 文档网格：`linePitch=576`，即 28.8 pt。

## 默认正文

`docDefaults`：

- 默认字号：16 pt（三号）。
- 固定行距：28.8 pt。
- 两端对齐。

`正文（默认）`：

- 中文：仿宋_GB2312。
- 西文：Times New Roman。
- 首行缩进：`640` twips，约两汉字。

| Heading 1 / 标题 1 | 文档主标题（公文标题） | 方正小标宋简体 | 22 pt（二号） | 居中，固定 35 pt |

| Heading 3 / 标题 3 | 正文二级标题 | 楷体_GB2312 | 16 pt（三号） | 左对齐 |

模板示例可见编号采用 `一、`、`（一）`、`1.`、`（1）`。

## 目录

- `目录标题`：方正小标宋简体，22 pt，居中，固定 35 pt。
- `目录一级条目`：黑体。
- `目录二级条目`：楷体_GB2312；左缩进 `640` twips。
- `目录三级条目`：仿宋_GB2312；左缩进 `1280` twips。
- 西文使用 Times New Roman。

## 页码与页脚

- 偶数页：左对齐，左缩进 `-280` twips。
- 奇数页：右对齐，右缩进 `-280` twips。
- 页码格式：`— PAGE —`。
- 页码字体：宋体，14 pt（四号）。

## Word Online 中西文字体兼容经验

已通过同一 DOCX 的多轮 OneDrive / Word Online 对照测试确认：

1. 单纯把 `仿宋_GB2312` 改成 `FangSong` 不能解决显示不一致。
2. 同步修改 `fontTable.xml` 仍不能解决。
3. `themeFontLang eastAsia=zh-CN` 应保留，但单独设置它不足以解决问题。
4. 真正有效的处理是：把同一个纯文本 run 内的中文与 ASCII 英文/数字拆成不同 run。
5. 中文 run 保持模板要求的中文字体，例如正文 `仿宋_GB2312`；英文/数字 run 使用 Times New Roman。
6. 拆分后的每个 run 都显式写入东亚字体槽和西文字体槽。

因此，本 Skill 不采用“把公文字体统一改成 FangSong”的方案，而采用“保留模板字体 + 中西文分 Run + 显式字体槽”的方案。

例如原来：

```text
[2021年以来，北京北矿智能科技有限公司……]
```

应规范为：

```text
[2021] → Times New Roman
[年以来，北京北矿智能科技有限公司……] → 仿宋_GB2312
```

正文内容本身不得改变。

## OOXML 维护注意

不要使用 `xml.etree.ElementTree` 对 `document.xml` 或 `styles.xml` 做整体重写。格式修改应使用 `python-docx + lxml` 在现有 XML 树上局部操作。

中西文 run 拆分只处理普通 `w:t` 纯文本 run。含域、绘图、制表符、换行等特殊节点的 run 必须保留原结构，避免为了字体兼容破坏 Word 对象。
